# Architecture

One NestJS API process hosts identity, inventory, assessment, evidence, reporting, policy and findings domains. Next.js is the existing console and same-origin backend-for-frontend. Shared TypeScript engines remain source modules; the durable CPM assessment worker is a separate process using the same domain/repository code. The optional Go block indexer still invokes the assessment API with a local checkpoint.

PostgreSQL is authoritative for evidence, base assessments, canonical assets, graph relationships, immutable policy versions, assignments, schedules, jobs, leases, RPC budgets, posture snapshots, invalidations, drift, recommendations, migration assessments, findings, notifications and audit. Composite tenant foreign keys and forced RLS constrain all records. Redis is a disposable shared API request-quota store; its failure denies requests without losing job or evidence state.

The EVM connector obtains hash-pinned finalized account reads. Optional verified legacy/type-1/type-2 transactions establish an observed ECDSA-secp256k1 dependency and recoverable public key. The explicit ownable ERC20 adapter provides accessor evidence only. Existing CBOM/QBOM schemas are preserved. CPM references their evidence through immutable snapshots, fixed executable rule kinds and versioned data-only policies. Exposure cannot be hidden by disabling a rule; missing data remains unknown.

The worker leases scheduled jobs transactionally, rechecks provider canonicality, collects evidence and atomically commits assessment, posture, drift, findings and job success. On-demand assessments retain their existing idempotent base write followed by idempotent CPM evaluation; retry recovers a saved base record if the CPM transaction failed. These two transactions are not misrepresented as atomic. Bounded failures and invalidations are separate from historical classification.

Finding identity is tenant/asset/policy/rule. Repeated observations do not create duplicate lifecycle events. Exceptions and administrative closure preserve evidence. Only a pending-verification finding with the same rule semantics and a later finalized satisfied condition becomes technically resolved. Invalidated verification reopens it. Migration results separately verify explicit owner-accessor or bytecode properties and never execute a blockchain transaction.

The console and generated SDK expose real posture/history, monitoring health, drift, recommendation explanations and scoped migration results. Operator importance can raise remediation priority for a verified dependency; no TVL, causal authority propagation, quantum-arrival probability or fabricated score is inferred. Unknown custody/authorization produces NEEDS_EVIDENCE.

Deferred infrastructure includes external notification delivery, browser SSO, object storage, telemetry exporters, managed deployment manifests and external audit anchoring. Validator/bridge/custody/ZK/PQC execution adapters remain outside this implementation. See the CPM assurance report and assessment-worker runbook for exact operational limits.
