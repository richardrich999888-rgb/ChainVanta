# Security boundaries

The API derives tenant and role from an opaque credential or verified OIDC JWT and operator-owned memberships. JWT tenant/role claims are not trusted. Viewers read, analysts collect/schedule/assess migrations, and administrators manage policies, assignments, finding transitions and cancellation. Every CPM endpoint is authenticated, quota-controlled and tenant-scoped. Policy JSON selects fixed rule kinds and cannot execute code.

PostgreSQL transactions set `app.tenant_id` locally. Composite tenant keys, referential constraints and forced RLS cover all existing and CPM tables. Runtime startup rejects superuser/BYPASSRLS identities. Separate migration credentials provision schemas and tenants. Append-only triggers protect evidence, policies, snapshots, invalidations, findings, recommendations, migration results, notifications and audit from runtime mutation. Operational tables have narrowly scoped mutation grants. RLS protects missing predicates, not arbitrary SQL execution with the runtime role or privileged database compromise.

A tenant lock plus row locking and lease tokens coordinate scheduled work across replicas. The database holds schedules, attempts, deadlines and shared tenant/chain RPC counters. A late or cancelled worker cannot commit. Successful scheduled assessments and derived CPM results commit atomically; timeouts, provider errors and budget exhaustion produce failure events while retaining previous findings. On-demand collection retains the foundation's process-local concurrency cap; Redis limits requests across API nodes, and CPM derivation is a separate idempotent transaction after its base write.

RPC URLs are operator-configured, never accepted in assessment bodies. Production requires HTTPS and rejects demonstration chains. The Node transport validates all DNS answers, rejects private/metadata/loopback and special-address ranges, and supplies a checked answer directly to socket lookup. It disables pooling, rejects redirects, permits only supported read-only JSON-RPC methods, preserves TLS hostname verification, and bounds request/response sizes and duration. Loopback HTTP is allowed only for explicit non-production demonstration providers. Infrastructure egress rules remain defense in depth; HTTPS providers can still lie about chain state.

Provider canonicality rechecks append invalidations to dependent posture and migration projections. Invalidated verification cannot retain an effective technical-resolution claim. Original evidence and policy results remain available as historical records. No independent consensus proofs, cryptographic transparency anchoring or privileged tamper resistance are asserted. Supported type 0/1/2 transaction signatures are verified with the existing viem implementation; no custom signature primitives were introduced.

Finding transitions are authorized and append-only. Administrators can acknowledge, remediate, request verification, record an expiring exception or administratively close; they cannot label technical resolution. The older finding endpoint delegates supported CPM findings to the same lifecycle. Policy disablement preserves outstanding findings. A later satisfied rule with identical semantics can resolve only its defined evidence requirement. Removing a signature observation never resolves quantum exposure.

Console cookies retain HttpOnly, SameSite=Strict, production Secure and origin checks. Browser OIDC login and server-side session/credential rotation workflows remain outside this scope. Configure HTTPS and exact `WEB_ORIGIN`, managed secrets, private authenticated/TLS PostgreSQL and Redis, encrypted volumes and backup policies before deployment. Local Compose is development-only.

Audit and evidence hashes detect content changes under the runtime trust boundary; a privileged actor replacing data and hashes remains outside that protection. Append-only history has no automatic destructive retention. Only terminal jobs and old heartbeat rows are pruned. Establish tested restore/archive procedures and storage alarms.

Production rollout requires deployment-specific provider/finality validation, secrets/TLS/network setup, sustained-load and recovery tests, monitoring/alert delivery, an independent security review and an approved release. Those operational gates were not performed on customer infrastructure by this task. No certification, formal verification or unconditional production-readiness claim is made.
